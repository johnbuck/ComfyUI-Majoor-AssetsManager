**Title:** Recursive scan indexes files inside hidden folders (`.Trash-<uid>`), so deleted assets come back as cards

### Summary

A recursive scan descends into every subdirectory of a root, including hidden ones. On Linux,
`send2trash` (which Majoor's delete uses) moves a file on a non-home volume into
`<volume>/.Trash-<uid>/files/`. When that volume is the output directory, or contains it, the next
recursive scan of output walks `.Trash-1000/files`, and every deleted image is indexed again as a
live asset.

The watcher already ignores Majoor's internal folders (`IGNORED_DIRS` in
`mjr_am_backend/features/index/watcher.py`), and the folder browser hides dot-folders
(`_is_hidden_directory` in `features/browser/service.py`). The scan walker
(`FileSystemWalker._next_dir` in `features/index/fs_walker.py`) checks neither, so it also walks
`_mjr_index`, `.git`, `__pycache__` and `node_modules`.

### Reproducer (current main, 599b47df)

From the repo root, with the dev requirements installed:

```python
import tempfile
from pathlib import Path

from mjr_am_backend.features.index.fs_walker import FileSystemWalker

root = Path(tempfile.mkdtemp())
(root / "live.png").write_bytes(b"png")
trash = root / ".Trash-1000" / "files"
trash.mkdir(parents=True)
(trash / "deleted.png").write_bytes(b"png")
(root / "_mjr_index").mkdir()
(root / "_mjr_index" / "internal.png").write_bytes(b"png")

found = sorted(p.name for p in FileSystemWalker(scan_iops_limit=0.0).iter_files(root, recursive=True))
print(found)
```

**Expected:** `['live.png']`
**Actual:** `['deleted.png', 'internal.png', 'live.png']`

Real-world effect: after deleting a few hundred images from the grid and running a rescan, all of
them reappeared as cards (the files physically sit in `.Trash-<uid>/files`).

### Proposed fix

When the recursive walk meets a subdirectory, skip it if its name starts with `.` or is one of the
internal names the watcher already ignores. Share one set of names between the walker and the
watcher. The rule applies only below the scan root, so a root that itself lives under a dot-path
(for example `~/.config/ComfyUI/output`) keeps working, matching the watcher's MED-04 note.

I have a branch with the fix and tests (the tests fail on current main) and can open a PR if this
direction is acceptable.
