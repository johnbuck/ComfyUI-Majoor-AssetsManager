**Title:** feat: bulk tag add/remove across a selection

Part of #278 (bulk tag and rating edits). The rating half is a separate PR.

### What changed and why

Tags could only be edited one card at a time. This adds a batch route that merges tags on the server
and a bulk editor for multi-card selections.

**Backend**

- `POST /mjr/am/assets/tags {ids, add, remove}` (`routes/assets/route_actions_batch_tags.py`):
  - **Merge.** Per asset, computes `(existing ∪ add) − remove` case-insensitively. Existing casing is
    kept, and the merge runs inside the existing per-asset lock with no transaction spanning assets.
  - **Writes.** It writes only when the set changes, and enqueues the ExifTool sync only for changed
    assets (honouring `X-MJR-RTSYNC`).
  - **Validation and limits.** `add` and `remove` go through the existing `sanitize_tags`. Ids are
    deduped and capped at 500; the route allows 10 requests per minute.
  - **Partial results.** `{updated_ids, unchanged_ids, failed: [{id, code, error}], tags}`, with one
    audit entry per request.
  - **Tag cap.** The 50-tag cap rejects a merge that would add a new tag beyond 50. Pure removals
    still work on older assets that are already over the cap.
- `AssetUpdater.merge_asset_tags` holds the merge logic. `_write_asset_tags_locked` was extracted so
  the merge can write while holding the lock.
- `security_policy.py`: `assets_tags` is gated exactly like `asset_tags`. Safe mode otherwise refuses
  unknown operation names.

**UI**

- "Edit tags (N selected)" appears when the right-clicked card is part of a multi-selection.
  Otherwise the single-card editor is unchanged.
- `BulkTagsEditor.vue` (new) hydrates the selection's current tags through `getAssetsBatch` and shows
  each tag's coverage, e.g. `portrait (37/100)`.
  - Typing a tag adds it to every card. ✕ removes it from every card. Clicking a partially covered
    tag completes it.
  - Requests go out in sequential 500-id chunks, with a progress toast.
  - It dispatches `mjr:asset-tags-changed` per updated asset, so badges, the sidebar and the viewer
    refresh.
  - Workflow-kind assets are skipped and reported. They use the workflows tags endpoint, as in
    `updateAssetTags`.
  - Invalid input, the tag cap and incomplete hydration each show a warning toast.

### How to test

- pytest:
  - merge semantics, including add/remove overlap, case-insensitivity, unchanged detection and the
    cap with older over-cap assets;
  - the route: validation, missing ids, dedupe, rate limit, sync enqueue and audit;
  - a test against the real safe-mode gate.
- Vitest (`ui/tests/bulk_tags_editor.vitest.ts`): coverage display, add/remove/complete, chunking,
  skips, warnings, busy state, and right-click gating.
- Manual: select several cards, right-click one of them, **Edit tags (N selected)**, add "x" and
  remove "y". Every card gets "x", none keeps "y", and other tags are untouched.
