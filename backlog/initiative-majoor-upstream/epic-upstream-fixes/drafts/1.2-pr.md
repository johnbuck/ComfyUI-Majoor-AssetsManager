**Title:** fix(tags): replace XMP/IPTC tag lists instead of appending on save

Fixes #272

### What changed and why

Each rating or tag save appended to `XMP:Subject` and `IPTC:Keywords` instead of replacing them. Three
saves (`["cat"]`, `["cat","dog"]`, `["dog"]`) left 16 entries instead of `["dog"]`. All three causes
described in #272 are fixed in one commit:

- `adapters/tools/exiftool.py`: `_append_metadata_write_args` now writes a list as one plain
  `-TAG=item` per item. A bare `-TAG=` remains only for an empty list (or one holding only
  blanks/`None`), where it clears the tag. Previously it wrote `-TAG=` followed by `-TAG+=item`.
- `features/tags/sync.py`: the payload no longer writes unqualified `Keywords`/`Subject`. ExifTool
  resolved those to the same list tags and added a joined `"a; b"` item.
- `features/tags/sync.py`: the rating/tags write uses `preserve_workflow=False`. `-tagsFromFile @`
  copied the old list items back over the new values. ExifTool keeps tags it is not told to change,
  and the round-trip test confirms the PNG `prompt`/`workflow` chunks survive. The
  `preserve_workflow` parameter itself is unchanged for other callers.

### How to test

- Unit tests (run in CI without ExifTool):
  - `tests/features/test_exiftool_adapter.py` covers list arguments, empty-list clear, and lists of
    only blanks.
  - `tests/features/test_tags_sync.py` covers the absence of unqualified keys and checks that
    `preserve_workflow=False` is passed.
- `tests/features/test_tags_sync_exiftool_roundtrip.py` (new, skipped when `exiftool` is not on PATH):
  - Four saves on a synthetic PNG read back exactly `["dog"]` and then `["dog", "bird"]`, with the
    `prompt`/`workflow` chunks unchanged.
  - Clearing tags removes both list tags.
- On current main, the unit tests fail and the round trip fails on duplicated entries.
- The reproducer in #272 prints `dog` with this branch.
