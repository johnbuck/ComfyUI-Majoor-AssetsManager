**Title:** feat(ui): context-menu registry for extensions

Closes #ISSUE

### What changed and why

Other extensions can now add items to Majoor's grid and viewer context menus through a small public
API, instead of watching the DOM for the teleported menu.

```js
const api = window.MajoorAssetsManager?.api ?? await new Promise((r) =>
    window.addEventListener("mjr:api-ready", (e) => r(e.detail), { once: true }));
api.contextMenu.register({
    id: "my-ext.example",
    menus: ["grid-asset"],
    items: (ctx) => [{ label: `Do something with ${ctx.selection.count}`, onSelect: () => {} }],
});
```

- `ui/features/contextmenu/menuRegistry.ts` (new) holds the registry and validation. It turns
  extension items into Majoor's own `createItem` objects, so they render through the existing Vue
  menu with no component changes.
- `GridContextMenu.ts` (asset, empty-area and folder menus) and `ViewerContextMenu.ts` append
  registered items after Majoor's own, below one separator.
- `ui/entry.ts` exposes `window.MajoorAssetsManager.api` (`version: 1`) and fires `mjr:api-ready`
  early in setup. Registrations take effect the next time a menu opens.
- **Isolation.** A throwing or invalid `items()` is skipped with a warning, and invalid items are
  dropped. A throwing or rejected `onSelect` becomes an error toast. Majoor's menu always opens.
- **Context.** The context is a frozen snapshot with no DOM nodes and no live asset objects. Assets
  are projected to `{ id, filename, subfolder, filepath, type, kind, rating, tags }`.
- `docs/EXTENSION_API.md` (new) documents the API, the guarantees and an example. It is linked from
  `DOCUMENTATION_INDEX.md`.

### Design note

The API is a `window` global plus a module-level registry. `CONTRIBUTING.md` asks for Pinia and no
global mutable objects, but a surface meant for *other* extensions has to be reachable from outside
Majoor's bundle. The alternative of a hook on ComfyUI's `app.registerExtension` objects is question 1
in #ISSUE. I'm happy to switch if you prefer it.

### How to test

- `ui/tests/menu_registry.vitest.ts` (24 tests): no registrations leaves menus unchanged; ordering;
  replace by id; unregister; menu filtering; `items()` throwing or returning a non-array; invalid
  items; rejected `onSelect`; submenus and separators; frozen snapshot; `mjr:api-ready` and
  re-exposure; full `bindGridContextMenu` wiring.
- Manual: paste the snippet above into the browser console, then right-click a card.
