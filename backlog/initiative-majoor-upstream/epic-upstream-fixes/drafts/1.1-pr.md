**Title:** fix(index): skip hidden and internal folders in recursive scan

Fixes #271

### What changed and why

A recursive scan descended into every subdirectory. On Linux, `send2trash` moves a file deleted from
a non-home volume into `<volume>/.Trash-<uid>/files/`, so after a rescan every image deleted from the
grid came back as a card. On Windows the same applies to `$RECYCLE.BIN` when a root is a drive root.
The scan also walked `_mjr_index`, `.git`, `__pycache__` and `node_modules`.

- `fs_walker.py`: `FileSystemWalker._next_dir` no longer descends into a subdirectory whose name starts
  with `.` or is in the internal-folder list (the watcher's existing list plus `$RECYCLE.BIN` and
  `System Volume Information`, matched case-insensitively).
- That list, `IGNORED_DIR_NAMES`, now lives in `fs_walker.py`. `watcher.py` imports it as
  `IGNORED_DIRS`, so the scan and the watcher share one list. The watcher's matching logic is unchanged.
- The rule applies only below the scan root. A root that itself sits under a dot-path, such as
  `~/.config/ComfyUI/output`, still scans, in line with the watcher's MED-04 note.
- File-level filtering is unchanged. A dot-prefixed *file* is handled exactly as before.

### How to test

  and case-insensitive tests fail on current main; the regression tests (normal nested folder, dot-path
  root, dot-prefixed file) pass both before and after.

### Breaking changes

None. A user who deliberately keeps assets in a dot-prefixed subfolder of a root will no longer see
them indexed by a recursive scan. That is consistent with the folder browser, which already hides
dot-folders.
