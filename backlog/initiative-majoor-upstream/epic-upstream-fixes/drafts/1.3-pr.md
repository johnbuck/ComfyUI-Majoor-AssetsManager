**Title:** feat(config): make delete and asset-write rate limits configurable

Closes #273

### What changed and why

The single-asset delete route (20/min) and the rating/tags write routes (30/min) had hard-coded
per-client caps. Multi-card delete and rating hotkeys send one request per card, so larger selections
failed partway with `RATE_LIMITED`, and an operator could not raise the caps without editing code.

- `config.py`: adds `DELETE_RATE_LIMIT_PER_MIN` (`MJR_AM_DELETE_RATE_LIMIT`, default 20) and
  `ASSET_WRITE_RATE_LIMIT_PER_MIN` (`MJR_AM_ASSET_WRITE_RATE_LIMIT`, default 30). Both are read with
  the existing `_env_int` helper and clamped to 1–10000 per 60 s. Invalid values fall back to the
  default with the helper's usual warning.
- `routes/assets/route_actions_delete.py` and `_prepare_asset_op_request` in
  `routes/handlers/assets_impl.py` use the constants instead of the literals.
- Docs: a "Tunable Write Limits" subsection under Rate Limiting in `docs/SECURITY_ENV_VARS.md`, and
  both variables added to the env list in `docs/SETTINGS_CONFIGURATION.md`.

Defaults are unchanged, and the rename and batch-delete limits are untouched. Values are read at
startup like the other `_env_int` knobs.

### How to test

- `tests/config/test_rate_limit_knobs.py` (new): unset gives defaults; a valid value is used;
  non-integer falls back; below and above range clamp.
- `tests/features/test_assets_impl_routes.py`: the delete, rating and tags routes pass the
  configured `max_requests`, both at the defaults and with a knob set to 600.
- Manually: start with `MJR_AM_DELETE_RATE_LIMIT=600`, select 25+ cards, and delete. All are removed.
