**Title:** fix(grid): delete multi-card selections through the bulk endpoint

Fixes #ISSUE

### What changed and why

"Delete N files…" and the Delete key on a selection sent one `POST /mjr/am/asset/delete` per card,
capped at 20 requests per minute, so large selections failed partway. Both now use the existing bulk
endpoint.

- `ui/features/grid/bulkDelete.ts` (new): `deleteAssetsInChunks()` sends sequential chunks of at most
  500 ids. A progress toast appears for multi-chunk deletes.
  - **Rejected chunk with named entries.** Bulk validation is all-or-nothing, so one stale or
    out-of-root entry rejects the whole chunk before anything is deleted. When the server names the
    offending entries, the helper drops them (reported as failed) and retries the rest in bulk, up to
    3 attempts.
  - **Rejected chunk with nothing named**, or attempts exhausted: per-file fallback.
  - **Rate-limited chunk:** reported as failed, not hammered with single deletes.
  - **Filepath-only cards** (no id) keep using the single-delete call.
- `GridContextMenu.ts` and `GridKeyboard.ts` use the helper. Confirmation, toasts, card removal and
  selection updates are unchanged.
- `ui/api/clientOps.ts`: `deleteAssets()` emitted `mjr:assets-deleted` for every requested id, even
  after a partial failure. It now emits only the server's `deleted_ids`.
- `route_actions_batch_delete.py`: rejections now carry `meta.missing_ids` (NOT_FOUND) or
  `meta.rejected_ids` (FORBIDDEN / INVALID_INPUT). Validation now checks every row, so all offending
  ids are named at once. This is additive: codes, messages and the all-or-nothing behaviour are
  unchanged.
- `docs/API_REFERENCE.md`: the bulk delete request body is `{"ids": [...]}`, not `asset_ids`. The
  response and error examples now match the handler.

### How to test

- `ui/tests/bulk_delete.vitest.ts` (15 tests) covers:
  - chunking, partial results and unconfirmed ids;
  - named-id retries (NOT_FOUND then FORBIDDEN then ok);
  - attempt exhaustion, the rate-limited chunk and the unnamed-rejection fallback;
  - filepath-only cards and exceptions;
  - the event payload;
  - menu and keyboard wiring, where one bulk call is made and no single deletes.
- `tests/features/test_assets_impl_routes.py` (+3) checks `missing_ids`, a single `rejected_ids`
  entry, and two `rejected_ids` aggregated.
- Manual: select 30+ cards, right-click, **Delete N files…**. All are removed with one request.
