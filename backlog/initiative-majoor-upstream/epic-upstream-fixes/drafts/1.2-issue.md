**Title:** Saving rating/tags duplicates XMP:Subject and IPTC:Keywords entries on every write

### Summary

Each rating or tag save through ExifTool appends to the file's tag lists instead of replacing them.
After a few saves, `XMP:Subject` and `IPTC:Keywords` hold many copies of old tags plus joined
`"a; b"` entries. External tools that read those fields (Lightroom, digiKam, Windows Explorer) show
the duplicates.

### Reproducer (current main, 599b47df, ExifTool 12.x on PATH)

From the repo root, with the dev requirements installed:

```python
import json, subprocess, tempfile
from pathlib import Path
from PIL import Image, PngImagePlugin
from mjr_am_backend.adapters.tools.exiftool import ExifTool
from mjr_am_backend.features.tags.sync import write_exif_rating_tags

p = Path(tempfile.mkdtemp()) / "synthetic.png"
info = PngImagePlugin.PngInfo()
info.add_text("workflow", '{"nodes": []}')
Image.new("RGB", (8, 8)).save(p, pnginfo=info)

ex = ExifTool()
for rating, tags in [(3, ["cat"]), (4, ["cat", "dog"]), (5, ["dog"])]:
    write_exif_rating_tags(ex, str(p), rating, tags)

print(json.loads(subprocess.check_output(["exiftool", "-j", "-XMP:Subject", str(p)]))[0]["Subject"])
```

**Expected:** `dog`
**Actual:** 16 entries: `cat` ×10, `dog` ×4, `cat; dog` ×2. `IPTC:Keywords` is identical.

### Causes

Three separate causes compound:

1. `ExifTool._append_metadata_write_args` writes a list as `-TAG=` followed by `-TAG+=item`. Within one
   command, `+=` adds to the values already in the file, and the preceding empty `=` does not clear
   them first.
2. `_build_exiftool_rating_tags_payload` also writes unqualified `Keywords` and `Subject` as a joined
   string. ExifTool resolves those names to `IPTC:Keywords` and `XMP-dc:Subject`, the same list tags,
   so each save adds one `"a; b"` item.
3. `_write_exiftool_payload` calls `write(..., preserve_workflow=True)`, which adds
   `-tagsFromFile @`. With no tag list, that copies every existing tag back onto the file, so the
   old list items return even after a plain `=` assignment.

### Proposed fix

- Write a list as one plain `-TAG=item` per item. A bare `-TAG=` is kept only for an empty list,
  where it deletes the tag.
- Drop the unqualified `Keywords`/`Subject` keys from the payload.
- Use `preserve_workflow=False` for the rating/tags write. ExifTool keeps tags it is not told to
  change, so ComfyUI's `prompt`/`workflow` PNG chunks survive. A round-trip test checks this.
  `preserve_workflow` stays available for the other callers.

I have a branch with the fix, unit tests for the argument building, and a real-ExifTool round-trip
test (skipped when ExifTool is absent). I can open a PR if this approach suits you.
